    Charge each order once when a provider timeout is retried
    
    charge_order retried after a ProviderTimeout without an idempotency key.
    The provider records the charge before the timeout loses its response, so
    each retry created another charge on the same order (ORD-100953).
    
    Every attempt to charge an order now sends the same idempotency key
    (charge:<order_id>), and the provider returns the original charge for a
    repeat key. Adds a regression test that times out the first attempt,
    retries, and asserts exactly one charge exists.
